**핵심 경계선은 "생산 구간"과 "가공 구간" 사이다.** LLM은 도구를 호출해 데이터를 가져오고
(F3에서는 노트 문장까지) 만들지만, **출처 부착·게이트 판정·저장은 전부 결정적 코드**가 한다.
게이트가 LLM 판단이면 프롬프트 인젝션 한 줄로 무력화되기 때문이다.

**모델 3-tier 배치 근거**

| 에이전트 | 모델 | 왜 |
|---|---|---|
| O | Opus | 어느 에이전트에게 무엇을 넘길지 판단하는 자리. 여기서 틀리면 전체가 틀어진다 |
| a1 공시 수집 | Haiku | 도구 호출 + 목록 정규화. 판단이 거의 없다 |
| a2 실적 수치 | Sonnet | 재무제표 항목 대응·전기 대비 계산에 해석이 들어간다 |
| a4 뉴스 | Haiku | 검색 결과에서 관련 기사 골라내기 |
| A5 노트 초안 | Opus | 유일하게 사람이 읽는 산문을 쓴다. 각주 규칙 준수가 최대 리스크라 여기서 아끼지 않는다 |

## 3. 컴포넌트 → Agent SDK 매핑표

`claude-agent-sdk==0.2.110` 실물 기준. 에이전트 루프·위임·팬아웃/팬인은 전부 SDK가 처리하고,
**직접 짠 루프는 없다.**

| 우리 컴포넌트 | Agent SDK 프리미티브 | 코드 위치 |
|---|---|---|
| 에이전트 실행 | `query(prompt, options)` | `main.py::research_stream`, `::_collect_brief_data` |
| 오케스트레이터 지침 | `ClaudeAgentOptions(system_prompt=...)` | `main.py` (F3 인라인 / `BRIEF_SYSTEM_PROMPT`) |
| 서브에이전트 정의 | `.claude/agents/*.md` frontmatter (`name`·`description`·`model`·`tools`) | `a1·a2·a4·a5.md` |
| 위임(팬아웃/팬인) | `Agent` 도구 — SDK가 자동 노출 | O의 프롬프트가 위임 순서만 지시 |
| 자체 도구 | MCP stdio 서버 3종 | `.mcp.json` → `backend/mcp_servers/*` |
| 감사로그 훅 | `hooks={"PreToolUse": [HookMatcher(...)], "PostToolUse": [...]}` | `main.py::_pre_tool_use_hook`, `_post_tool_use_hook` |
| 도구 허용 목록 | `can_use_tool` 권한 콜백 → `PermissionResultAllow/Deny` | `main.py::can_use_tool` |
| A5 도구 차단 | `can_use_tool` 전면 거부 + `max_turns=1` | `main.py::_deny_all_tools` |
| 토큰 스트리밍 | `include_partial_messages=True` + `StreamEvent` | `main.py::_text_delta` → `note_token` SSE |
| 에이전트 귀속 | 메시지의 `parent_tool_use_id` | `main.py` 진행 이벤트 매핑 |
| 결과 수집 | `AssistantMessage`·`UserMessage`·`ToolUseBlock`·`ToolResultBlock`·`TextBlock` | `main.py` 스트림 루프 |

> ⚠️ `can_use_tool`을 쓰면 SDK가 `prompt`를 문자열이 아니라 **AsyncIterable**로 요구한다
> (`main.py::_prompt_stream`이 그 최소 래퍼다). 이건 문서에 없어 실물로 확인했다.

## 4. 주요 의사결정과 근거

### 4.1 A5만 위임하지 않고 백엔드가 직접 실행한다

**문제**: 라이브에서 노트가 한 번도 생성되지 않았다. `Agent` 도구는 **비동기**다 — 결과가
`"Async agent launched successfully"`로 즉시 돌아오고 서브에이전트는 백그라운드에서 돈다.
메인 에이전트가 턴을 끝내면 스트림이 닫히고 안 끝난 서브에이전트는 잘린다. 도구를 호출하는
a1·a2·a4는 결과가 스트림에 빨리 들어와 살아남지만, **도구 없이 텍스트만 만드는 a5는 항상
잘렸다.**

**시도하고 되돌린 것**: 프롬프트에 "a5 결과를 반드시 기다려라"를 넣었더니 O는 기다리지 않고
**a2가 가져온 수치로 문장을 지어내 a5가 쓴 것처럼 인용했다**(가드레일 3 위반). 지시를
강화할수록 날조 압력만 커진다.

**검증한 두 갈래** (`backend/scripts/background_flag_check.py`로 Haiku 저비용 판정):

| | 노트 도착 | 토큰 스트리밍 | `O→a5` 위임 | 각주 무결성 |
|---|---|---|---|---|
| 비동기(기본) | ❌ 잘림 | ❌ | ✅ | — |
| `background: false` | ✅ | ❌ 죽음 | ✅ | O가 다듬을 위험 잔존 |
| **채택: 백엔드 2차 `query()`** | ✅ | ✅ | ❌ | ✅ |

`background: false`는 실제로 동작하지만(위임이 동기가 된다), **동기 위임에서는 서브에이전트의
`StreamEvent`가 전혀 노출되지 않아**(실측 `parent_tool_use_id` 분포 `{None: N}`) 토큰
스트리밍이 죽는다. 그래서 a5는 `a5.md` 본문을 `system_prompt`로 읽어 **2차 `query()`의 메인
에이전트**로 돌린다.

**부수 효과가 오히려 개선이다.** 예전에는 O가 a2·a4 결과를 텍스트로 옮겨 a5에게 넘겼는데,
그 과정에서 URL·접수번호가 다듬어지면 각주가 깨진다. 이제 backend가 도구 결과를 구조화된
그대로 직렬화해(`_a5_input()`) 넘기므로 그 위험이 사라졌다.

**잃은 것**: 토폴로지에서 `O→a5` 위임 한 단계. 팬아웃 3단계는 그대로다.

### 4.2 F2에서 LLM이 하는 일은 "고른 결과를 문장으로 옮기는 것"뿐이다

원래 F2 브리프는 **에이전트가 한 문장도 쓰지 않았다.** 지금은 두 줄까지 LLM이 쓰지만
(고객 관련 종목), 원칙은 그대로다 — **무엇을 올릴지는 전부 규칙이 정하고 모델은 문장만 쓴다.**

| | 규칙(코드) | LLM |
|---|---|---|
| 평소 대비·유의사항 | 조회·판정·문장까지 전부 | (없음) |
| 3개월 추세 줄 | 어느 지표인가·변화폭·기간 배지 | 변화 수치 + 제목 → 한 문장 |
| 고객 관련 종목 줄 | 후보 종목·순서·등락률·보유 인원 배지 | 제목 + 비식별 맥락 → 한 문장 |

**단위가 다른 지표를 어떻게 견주나.** `+12%`와 `+40bp` 중 무엇이 크냐는 물음은 성립하지
않는다. 그래서 각 지표를 **자기 일간 변동으로 나눈다**(`z = 누적변화 ÷ (일간σ × √n)`) —
단위가 상쇄되고, 뜻도 분명하다("평소 흔들리는 폭에 비해 몇 배로 움직였나"). 화면과 프롬프트에
나가는 것은 **실제 변화폭**이고 z는 고르는 기준으로만 쓴다 — z를 적으면 PB가 설명할 수 없는
숫자가 하나 는다.

**왜 고르기를 모델에 안 맡기나.** 종목을 모델이 고르면 각주를 어디에 붙일지도 모델이
정하게 되고, 그때 화면은 근거가 맞는지 확인할 방법이 없다 — `f1.rebalance_options`가
선택지를 규칙으로 뽑는 것과 같은 이유다.

**밤사이 거시 헤드라인 줄은 걷어냈다(2026-08-10).** 지표 띠와 `_delta_bullets`가 이미
"무엇이 달라졌나"를 답하고 있어서, 그 위에 시황 기사 요약이 한 줄 더 서면 같은 질문에 두 번
답하는 셈이었다. `pick_headlines`(신선도·중복 제거)만 남겨 종목 줄이 그대로 쓴다.

**실측으로 배운 것 (2026-08-10)**

- **각주는 문장이 말한 것만 가리켜야 한다.** 종목 뉴스 6건을 한 번에 넣었더니 서로 다른
  사건이 셋 섞였고, 한 문장이 다 담지 못하자 **언급하지 않은 기사가 각주로 붙었다.**
  종목이 곧 묶음이라 사건별로 더 가를 축이 없으므로 → **최신 3건으로 좁혔다**
  (`WATCH_NEWS_LIMIT`).
- **금지어는 낱말이 아니라 구문에 걸어야 한다.** 처음에 `권`·`확대`·`축소`·`비중을`을
  통째로 막았더니 `경영권`·`적자 축소` 같은 **사실 문장이 버려졌다.** 버려진 줄은 화면에서
  안 보이므로 넓은 금지어는 엄격이 아니라 **조용한 고장**이다. 지금은 `해야`·`권고`·
  `매수 시점`처럼 "그래서 하라"는 구문만 막고, **버린 사유를 로그에 남긴다**
  (`brief.stock_headline_reject`) — 안 그러면 "오늘은 관련 종목이 없었다"와 "검증에 걸렸다"를
  구별할 수 없다.

**비동기 위임 문제는 여전히 겪지 않는다** — F2에는 O가 없고 backend가 도구와 `query()`를
직접 부른다(위임이 없으니 잘릴 서브에이전트도 없다).

### 4.3 게이트 규칙은 SDK가 아니라 직접 작성한다

SDK 훅(PreToolUse/PostToolUse)과 권한 콜백은 **배선 지점**일 뿐이고, 판정 로직은
`backend/compliance.py`에 직접 썼다. 게이트가 LLM 판단이면 공시·뉴스 원문에 섞인
지시문 한 줄로 무력화될 수 있다. 규칙 5종:

| 규칙 | 내용 |
|---|---|
| 필수 고지문구 | 기능별로 다르다(`NOTICES`: F2=내부 참고용 + 내부 계좌데이터 명시 / F3=AI 초안 워터마크). 모르는 기능 코드는 `ValueError`로 터뜨린다 |
| 인용 누락 | 출처 없는 문장을 위반으로. **소제목은 예외**(`is_heading`) |
| 금지 표현 | 없는 확실성을 만드는 단정("무조건 오릅니다"·"수익을 보장"). **투자권유·광고성 표현 차단은 2026-08-10에 걷어냈다** — PB가 보는 화면이라 어떤 종목을 권할지 AI가 말해도 된다는 제품 결정이다. 구조는 남아 있어 문구만 넣으면 되살아난다 |
| 지연시세 명시 | 조건부 — 시세 단어(`QUOTE_TERMS`) **+ 실제 수치**가 함께 있을 때만 발동 |
| MNPI | 미공개중요정보 의심 패턴 |

**발행 시점에 다시 검사한다.** 초안 때 통과했더라도 미인용 문장이 남아 있으면 발행이
차단된다(409, 감사로그 기록). 사람이 승인 버튼을 눌러도 게이트를 우회할 수 없다.

### 4.4 지연시세 체크를 조건부로 좁혔다

처음에는 "본문에 시세 단어가 있는데 '지연시세'가 없으면 위반"이었다. 그러자 **F2의 빈 결과
안내문까지 위반 처리되는 오탐**이 실제로 났다. 지금은 시세 단어 + 실제 수치가 함께 있을
때만 발동하고, 가격 정규식이 `"7만원"`·`"1.7조원"` 같은 단위 표기도 잡는다.
라이브에서 뉴스 요지에 "주가"가 있었는데도 발동하지 않는 것을 확인했다.

### 4.5 출처 해상도는 "문서 + 접수시점"까지다

계획서 원문은 "문서·**페이지**·접수시점"을 요구했지만, **DART 전자공시는 PDF가 아니라 HTML
뷰어 문서라 페이지 번호라는 단위 자체가 없다.** 문서 링크(`viewer_url`) + 접수시점
(`rcept_dt`)이 이 데이터 소스에서 가능한 최대 해상도다. (원문의 표현은 PDF 기반 리서치
문서를 상정한 것으로 보인다.)

### 4.6 `dart_search`에 반환 상한을 뒀다

삼성전자 공시가 하루 **382건**인 날이 있었다(임원·주요주주 소유상황보고 대량 제출일 —
조회 버그가 아니라 실제 데이터). `days=90`이면 70,461자가 되어 도구 결과가 토큰 한도를 넘고,
**a1이 받은 건 데이터가 아니라 에러 문자열이었다.**

→ 기본 `limit=30` + DART API에 `sort=date&sort_mth=desc` 명시(잘라낸 30건이 곧 "가장
최근"이 되도록) + 필요한 만큼 모이면 남은 페이지를 받지 않음. **70,461자 → 4,654자.**

### 4.7 실패가 성공처럼 보이는 경우를 걸러낸다

토큰 한도 초과 결과는 `is_error=False`인 채로 `"Error: result (N characters) exceeds
maximum allowed tokens..."` 문자열로 돌아온다. 그대로 세면 진행 타임라인에 `completed`로
찍혀 원인을 못 찾는다. → `main.py::_tool_failed()`가 `is_error` 또는 해당 패턴을 실패로 본다
(`test_tool_result.py`로 고정 — 정상 데이터에 "error"라는 단어가 있어도 오판하지 않는지 포함).

### 4.8 공시 중요도 순위 — 지분공시는 빼지 않고 뒤로만 민다

대형주는 30일 공시가 177건이고 거의 전부 임원 지분 보고라, 그대로 실으면 중요 공시가 묻힌다.
순위는 `0=주요사항 1=정기 2=기타 3=지분`. **제외가 아니라 후순위**인 이유는 조용한 날
브리프가 비지 않게 하기 위해서다. DART 응답에 공시유형 필드가 없어 보고서명으로 분류한다.

### 4.9 도구 결과의 귀속은 도구 입력에서 가져온다

F2에서 어느 종목의 데이터인지 되짚어야 하는데, 처음에는 **위임 메시지에 처음 나온 종목코드**를
집었다. O가 위임문에 앞 종목을 함께 언급하면(예: "005930과 마찬가지로 000660을…") 조용히
남의 종목으로 귀속된다 — 틀려도 티가 안 나는 종류다.

지금은 `dart_search`의 **도구 입력에 있는 `stock_code`를 직접** 쓰고, 뉴스는 검색어를
`krx_quote`가 준 법인명과 대조한다. 어느 쪽으로도 확정할 수 없으면 **버린다** — 엉뚱한 종목
브리프에 남의 데이터를 싣느니 비는 편이 낫다(가드레일 3).

### 4.10 대시보드: 시안 서빙 → React 포팅

처음에는 `GET /dashboard`가 시안 HTML(`docs/design/pb-admin-dashboard.html`)을 그대로
반환했다. 복사본이 없어 시안과 실화면이 갈라지지 않는다는 이점이 있었지만, **부작용으로
노트 생성 카드가 목업 상태로 굳었다** — 자립형 HTML에 SSE를 배선하면 별도 화면(`page.tsx`)이
이미 하는 일을 중복 구현하는 셈이라 계속 미뤄졌고, 결과적으로 화면이 두 갈래로 남았다.
"플랫폼" 화면에서 핵심 데모(멀티에이전트 실시간 협업)가 가짜였다는 뜻이다.

지금은 React로 포팅해 하나로 합쳤다(`frontend/src/app/dashboard/`).

- 노트 생성 카드가 **실제 `/api/research/stream`을 구독**한다. `page.tsx`(F3 단독 화면)는
  이 카드로 흡수되고 `/`는 대시보드로 리다이렉트한다.
- **백엔드가 없으면 목업으로 폴백하지 않고 연결 실패를 그대로 말한다.** 폴백은 자립형
  시안 파일의 성질이지 실화면의 성질이 아니다 — 실화면이 조용히 가짜 데이터를 보여주면
  그게 더 위험하다. 목업으로 보고 싶으면 시안 파일을 직접 열면 된다.
- CSS는 시안의 `<style>` 블록을 **그대로** 옮겼다(번역 오류 방지). 토큰 스트리밍·부분결과
  카드 스타일만 "시안에 없는 추가분"으로 표시해 뒤에 붙였다.
- 시안이 하드코딩하던 추이 차트·컴플라이언스 알림·타일 수치를 **감사로그·세션에서 집계**로
  바꿨다. 시안은 컴플라이언스 알림에 "DB 실데이터" 배지를 달고도 하드코딩이어서 라벨과
  실제가 어긋나 있었다.

시안 파일은 **디자인 시안으로 남는다**(아티팩트 게시용·오프라인 열람용). 실화면과 갈라지지만,
포팅 후에는 그게 정상이다.

### 4.11 앱 안에 스케줄러를 두지 않았다

F2는 배치 트리거(`POST /api/briefs/run`)만 제공한다. 트리거가 하나 있으면 cron/CI 한 줄로
충분하고, 앱 안에 스케줄러를 두면 컨테이너 재시작·중복 실행을 직접 관리해야 한다.
데모에서는 원할 때 돌리는 수동 트리거가 오히려 낫다.

"기능 N개 비용 ≈ 공통 인프라 1 + 얇은 레이어 N"이 설계 목표였고, F2가 그 증거다.

|---|---|---|
| F3 | 에이전트 배선 · MCP 3종 · 게이트 · citations · 감사로그 · SSE | `a5.md` + 노트 라우트 |
| **F2** | 〃 그대로 | `brief.py` + 브리프 라우트 — **새 에이전트 0개** |
| H1 | 〃 그대로 | 조회 라우트 9개 |
| F4(예정) | 〃 그대로 | `a3.md` + 비교 화면 |
